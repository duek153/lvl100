# LVL100 — תוכנית מוצר, מחקר וארכיטקטורה

### חומרי הכנה רשמיים ורישוי
- ב[עמוד בחינות להתנסות](https://www.nite.org.il/other-tests/amirnet/practice-test/?lang=en) יש 3 בחינות אמירנט ממוחשבות להתנסות, ובארכיון יש בחינות אמיר לדוגמה (PDF) וחוברת הדרכה.
- **תנאי שימוש:** החומרים מיועדים "לשימוש אישי לא מסחרי, לצורך תרגול בלבד, כל הזכויות שמורות למאל"ו". **לכן אין להכניס אותם למאגר.** האתר רק מפנה אליהם בקישור ("תרגלו גם בבחינה הרשמית").
- כל התוכן במאגר (שאלות, קטעים והסברים) **מקורי**, ונכתב בסגנון הבחינה בלבד.

## 3. ארכיטקטורה
```
React 18 + TypeScript + Vite (SPA, HashRouter → אירוח סטטי בכל מקום)
│
├─ src/domain/      ← לוגיקה טהורה, ללא React וללא אחסון. זה הקוד שיעבור לשרת
│   xp, levels, streak, srs, adaptive, scoring (IRT-lite), simulation,
│   readiness, achievements, quests, plan, placement
├─ src/services/    ← GameService: פעולה → state חדש (recordAnswer, finishSession…)
├─ src/store/       ← Repository interface + LocalStorageRepository
│                      (בעתיד: SupabaseRepository עם אותו ממשק)
├─ src/data/        ← Content packs שנטענים ב-lazy (dynamic import → chunks נפרדים)
└─ src/pages, components
```
**מעבר ל-Supabase בלי לכתוב הכול מחדש:**
1. `Repository` הוא הממשק היחיד שהאפליקציה מכירה. מחליפים מימוש ולא דפים.
2. פונקציות `domain/` טהורות ונבדקות, ואפשר להריץ אותן כ-Edge Function או לתרגם אותן ל-SQL RPC.
3. ב-Supabase **הלקוח לא כותב XP או ציון**. הוא שולח רק `submit_answer(question_id, answer, ms)`, והשרת בודק, מחשב XP ומעדכן. RLS נועל את כל הטבלאות (`supabase/schema.sql`).

## 4. מבנה ה-Database (Supabase / PostgreSQL)
ראו `supabase/schema.sql`. טבלאות: `profiles`, `questions`, `question_options`, `reading_passages`, `vocabulary`, `user_vocabulary`, `answers`, `skill_ability`, `tests`, `test_attempts`, `achievements`, `user_achievements`, `daily_challenges`, `daily_activity` (streak), `friends`, `friend_challenges`, `reminders`, `xp_events`.
ב-MVP המקומי כל "טבלה" נשמרת תחת מפתח localStorage נפרד (`lvl100:answers`, `lvl100:vocab`…), כלומר בלי JSON ענק אחד.

## 6. User Flow
```
כניסה ראשונה → Onboarding (מטרה, רמה, ציון יעד, תאריך, ימים וזמן) → "Let's build your plan"
  → Placement Test (20 שאלות אדפטיביות) → תוצאה: רמה, ציון משוער, חוזקות וחולשות
  → Dashboard: משימת היום → Session → תוצאה + טעויות + XP → חזרה ל-Dashboard
כל יום: Daily Quest + Daily Challenge + חזרות SRS
כל Stage: תרגול → Boss Battle → Stage הבא; כל 5 Levels: Progress Test
מוכנות גבוהה → READY FOR AMIRNET → סימולציה מלאה → Estimated AmirNet Score
```

## 7. Gamification
- **XP:** נכונה +10 (+5 בקשה, +10 בקשה מאוד), בונוס מהירות +3, רצף 5 = +25, רצף 10 = +50, Daily Quest = +150, Daily Challenge = עד +120, Boss = +200, Progress Test = +250, סימולציה = +300, יום למידה ראשון = +50.
- **Levels:** 20 רמות עם שמות (Beginner → AmirNet Challenger). עקומת XP היא `100·n^1.5` מצטבר.
- **Streak:** יום עם 5 שאלות לפחות. Streak Freeze נקנה ב-XP (עד 2 שמורים) ומופעל אוטומטית על יום שהוחמץ.
- **Achievements:** 16 הישגים.
- **Bosses:** בסוף כל Stage (דרוש ≥ 70%).
- **Leaderboard:** יריבים מדומים עם תווית ברורה (עד שיהיה Backend), וגם מצב Private.
- **Friends:** אתגר חבר בקישור. הקישור מקודד seed של אותן 10 שאלות ואת התוצאה שלך. עובד בלי שרת.

## 8. Estimated Score — שקיפות
המנוע מחזיק יכולת θ לכל Skill (מודל Rasch/Elo פשוט). קושי השאלות מתורגם ל-b ∈ {-1.5, -0.5, 0.5, 1.5}. ציון משוער = `100 + 20·θ` (חסום ל-50–150), כך ש-θ=0 (הצלחה של 50% בשאלות בינוניות) ≈ 100.
**זה אומדן פנימי ולא כויל מול ציוני מאל"ו.** הדבר מוצג בכל מקום שבו מופיע ציון.
